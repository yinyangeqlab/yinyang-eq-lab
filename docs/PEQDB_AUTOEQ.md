## Application behavior

The comparison player and Tuning preview use unsmoothed PEQdB fitting by default. Listening Pool generation uses the same engine with 15 bands. Tuning exports add explicit PEQdB unsmoothed 10/15/20-band variants; existing Standard/Precise and Smooth/Close choices retain their existing algorithms and names. Previously saved presets remain readable.

The engine loads on demand in a dedicated worker when a headphone/target setup needs fitting. Requests include curve contents, band count, normalization purpose and the actual AudioContext sample rate. A 12-entry cache is additionally bounded to 500,000 serialized key characters. A 20-second timeout, worker construction/load failure, unsupported WASM/SIMD/rate, or invalid result falls back to our original fitter. Both targets in a comparison use one engine. Failed or cancelled work cannot apply to a changed setup; cancelled requests are not cached. The worker is terminated after 30 seconds idle and when its last pending request is aborted. Fallback results remain stable for the cached setup; reload to retry an engine that was unavailable.

Each request snapshots its input curves for fitting, fallback and caching. Retired worker callbacks cannot interrupt a replacement worker. Editing a measurement under the same ID invalidates finalized exports and cancels pending Tuning or Listening Pool generation; freshness follows curve contents as well as selection IDs.

A confirmed worker/load failure or timeout bypasses the engine for subsequent setups until page reload, avoiding repeated 20-second waits. A single unsupported fitting rate does not disable later supported requests. PEQdB fits at 44.1–192 kHz; other Web Audio rates within 3–768 kHz use the original fitter. Listening Pool fallback preserves its former Precise/Smooth algorithm; the additional Tuning fallback uses Precise/Close. Version strings identify the actual algorithm and metric. All export cards use the original weighted 241-point fit-error definition, while playback metadata identifies its separate 384-point metric.

EQ is prepared before playback. Initial and changed graphs remain muted until valid filters and headroom are installed. A Play action received while fitting is pending does not start audio later: the person presses Play again once ready. The common ready path keeps AudioContext resume and media play inside the user gesture. Changing a setup pauses its old audio; finishing a fit does not resume it. Normalization/loudness changes reuse the fitted filters.

Safari-compatible playback keeps resume and media play in the same initiating event for Library and passage playback as well. Tuning attaches its media source before metadata loading, avoiding WebKit's stalled late attachment, while native/OS media Play remains gated until an explicit initialization tap. Context suspension/interruption pauses media and listening progress, cancels pending playback intents, and asks for a fresh Play; becoming running again never starts media automatically. User volume/mute uses a separate output GainNode, so it also works when iOS ignores media-element volume. This output control does not change the fitter, normalization or export headroom.

Peak and shelf filters use explicit IIR coefficients, preserving shelf Q; Web Audio's native shelf nodes do not use Q in the same way. Stage replacement crossfades for 30 ms and retires old connections after 40 ms. Existing channel balance, loudness normalization, passage rules, participant consent and private-data separation remain. Headroom is evaluated across 44.1, 48 and 96 kHz plus the requested playback rate. A/B uses common attenuation. Library playback retains its existing limiter/ceiling. Preset exports retain filter type and six decimal places for gain/Q.

Loudness-only gain reductions and protected Library changes ramp over 5 ms; immediate attenuation remains available when changed filters or channel balance require headroom. Loudness-only Library changes reuse the IIR stages. PEQdB's upstream bounds allow ±16 dB per filter and shelf Q up to 3; these differ from the original shootout fitter's ±12 dB and 8 dB upper-treble caps. The local integration retains those explicit engine bounds and reports calculated headroom. This is a fitting-policy difference to evaluate before any public rollout.

PEQdB receives a correction normalized to the app's existing reference: mean 250–2500 Hz for playback comparisons, 1 kHz for exports. The application disables both adaptive smoothing and the optimizer's free overall-gain parameter. PEQdB's upstream top-octave rolloff remains. This explicit `unsmoothed-fixed-reference-v1` configuration differs from the earlier experimental benchmark's free-gain configuration. Do not mix their RMS values. Playback metadata records actual engine, configuration/version, sample rate, band count, RMS and preamp; the listening-run endpoint preserves these technical fields. Old records without those fields remain historical and are not relabeled.

## Build and local preview

Use pinned Node 26.12.0/npm 12.2.1 and the locked project dependencies. Install Emscripten 4.0.14 outside Git using its official emsdk distribution. Keep all downloaded C source/toolchain/measurement inputs outside Git.

```sh
python3 scripts/prepare-peqdb-autoeq.py \
  --inputs /tmp/peqdb-wasm-inputs/data \
  --emsdk /tmp/peqdb-wasm-inputs/emsdk \
  --gpl /path/to/complete/GPLv3-license.txt
node node_modules/vinext/dist/cli.js dev --port 5200
```

The script fetches and Git-blob-verifies pinned engine source from `peqdb/autoeq-c` commit `fdc0db772164387c2df8739742594197c6851fc3`. It renames the internal exp10 helper for libc portability and disables debug printing. Modified source files carry a dated change notice. No algorithm patch is applied. The wrapper's normalization is original application code. Generated engine JS/WASM, notices, source archive and hash manifest are ignored under `artifacts/peqdb-autoeq/`.

An empty isolated local database can be initialized once with `node scripts/init-local.mjs`; that command refuses existing application tables, creates ignored development secrets, and installs no target curves, recordings or production data. Do not run it against a populated checkout. Local review uses disposable, non-contributing fixtures without a production or admin session.

For a build, run the normal application build, prepare the engine/source package from the unchanged source, and then run `node scripts/package-static-assets.mjs --public-only` for a clone/local preview. Packaging verifies engine binaries, both license texts, runtime notices, source archive, current source file list and every packaged application's source hash before copying the engine package. The build records its source snapshot in `dist/peqdb-build-source.json`; packaging requires the same snapshot in the matching source archive. An absent/stale package or a build made from different source fails packaging. Dirty previews permit only the explicitly reviewed new source paths in `scripts/peqdb-source-allowlist.json`; other untracked files under source/data directories fail preparation and verification. Published build commands use relative paths. A public-only package remains explicitly nondeployable. Full production media packaging and deployment still require the separate established owner workflow and authorization.

No compiled engine or downloaded measurement is added to Git. A public clone without prepared engine assets can run the original fitter as fallback in dev; it must prepare the complete engine/source package before packaging a PEQdB-enabled build.

To replace the library, extract the source archive, install the pinned prerequisite toolchain, modify `modified-engine/src`, and run the recorded emcc build command with paths adjusted to your local directories. Keep the exported Emscripten API (`_malloc`, `_free`, `_preprocess`, `_autoeq`, smoothing getters and heap views) compatible. The application performs no runtime signature or hash check that blocks a compatible replacement. Build-time checks ensure that the source package corresponds to the binaries being packaged; rerun the preparation/package process after modifying its source. Users may adapt that process for their own replacement builds.

Build the accompanying original application with its locked dependencies, prepare its replacement engine package, initialize a fresh local database if needed, and run the dev server. When unpacking the application outside a Git checkout, run `git init` and `git add .` in the extracted `application/` folder to establish the local source inventory; no remote, commit or GitHub account is needed. The offer to download the matching source must remain available for as long as the matching engine binary is served; an upstream link alone does not replace it.

## Verification and limits

`scripts/check_peqdb_autoeq.mjs` executes the actual WASM on six pinned public measurements with the integrated normalization, checks explicit IIR math against the private-comparison coefficient implementation, checks shelf export/import precision, and exercises cache/input copies, retired worker callbacks, aborts, idle disposal, malformed output, worker restrictions and timeout fallback. It reads optional external real-measurement fixtures from the earlier local lab; those numerical inputs and outputs remain ignored. `scripts/check_main_workflows.mjs` executes the actual Tuning and library handlers with deferred fits, verifying same-ID measurement edits invalidate downloads and prevent stale fits from being finalized or saved.

`scripts/check_peqdb_browser.mjs` executes the actual MusicPanel in a disposable component fixture with a delayed engine, a blocked WASM fetch and a blocked Worker constructor. It checks uniform engine selection, stop-before-ready behavior, real IIR audio, no contribution requests, the integrated Tuning page at desktop/360px and license/source downloads. No production participant/admin browser is used. Existing playback request, passage, blind-comparison, upload, consent and source-selection regressions are also run. `scripts/check_peqdb_built.mjs` also executes the production-built worker against the packaged WASM, checking that it really uses PEQdB rather than silently falling back. `scripts/check_peqdb_package.mjs` verifies the binary/source/notices inventory and proves that added source files or altered package assets are rejected.

The browser and built-worker checks accept `AUTOEQ_BROWSER=webkit` and optional `AUTOEQ_DEVICE='iPhone 13'` or `'iPad Pro 11'`, using an installed Playwright WebKit browser. Set `AUTOEQ_PLAYWRIGHT` to an external Playwright module path if it is not in project dependencies; `AUTOEQ_WEBKIT_EXECUTABLE` optionally selects an isolated local launcher. The WebKit suite additionally runs real Tuning/Library playback and resumption, delays resume completion to check gesture ordering, models read-only element volume, checks actual output-gain volume/mute, and suspends real contexts to verify explicit recovery. The deterministic models supplement the real engine tests; they do not turn Linux device emulation into physical iOS certification. Native selects retain dark expanded options and room for focus outlines; their selected-value overflow is clipped separately from search popovers. Physical Apple hardware, OS lock/call interruptions, native codec differences and headphone listening remain unverified. See `docs/reviews/2026-10-28-peqdb-webkit.md` for scope, results and primary references.

Numerical fitting improvement is not proof of audible preference. Adaptive smoothing remains a separate policy decision. Before a future public rollout, preserve engine/configuration provenance and consider comparability with historical research; do not silently relabel previous measurements or records.
