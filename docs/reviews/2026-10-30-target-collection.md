# Targets collection first — local preview

The Targets section in My space now opens to saved/uploaded target rows and a count, with Add target as the explicit action. The existing upload form is a hidden disclosure below the collection. Add opens it and focuses Target name; Back to targets/Close form hides it and returns focus to Add target. The form remains mounted while toggled, preserving a draft and file input. Changing sections closes the disclosure so returning opens the collection view. Existing upload validation, private/public choices, review/withdrawal/removal/Undo controls, storage keys and successful Open comparison handoff remain.

Feedback is visible next to the collection instead of below the entire upload form. Empty collections have a brief explanation. Narrow rows give the name/status their full width and place actions beneath, retaining readable labels and44px action targets. The upload file-format and advanced reference instructions remain available inside Add target.

Inspection also found that the existing trial-preparation effect had no section guard: a qualified listening setup could reserve a pairing even while browsing My space or rankings. The effect now runs only on the listening section, and section changes cancel stale response handling through its dependencies. Existing trial-issuing/listening logic otherwise remains unchanged. The actual-handler suite covers the five non-listening sections making zero trial requests and the listening section still requesting a pairing; its prior21 upload/privacy/removal scenarios also pass.

Synthetic browser review uses read-only example collection rows outside Git and does not overwrite browser target records. Review covers empty/populated collection states, opening/closing and draft retention, keyboard focus, existing native select menus and narrow layouts. Final build, types, lint, regression evidence and exact source references are recorded in the matching handoff after checks complete.
