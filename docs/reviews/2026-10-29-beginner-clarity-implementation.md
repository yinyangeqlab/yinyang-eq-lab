# Beginner language and guidance implementation

October 29, 2026. Based on published main `3ecad7342063f1f228456967c71d17560e729043` and the October 28 update125 source audits. The owner authorized reviewing all suggestions, implementing the justified changes, committing, deploying and completing the handoff.

## Decisions applied

The existing Astra/Codex area audits and all 80 Claude suggestions were assessed. Duplicate observations were combined. Literal replacements that promised safe ear exposure, exact headphone correction, unique listeners, universal rankings, deletion everywhere, or unsupported per-record merging were rejected. Consent, scientific methods, scoring and data access remain the authority for wording.

- Welcome explains the activity before EQ terminology, defines target/measurement, puts detailed methods behind a disclosure and uses a single beginner action. Main Listen navigation opens the existing Personal starter; direct research/Open routes remain available.
- Headphone search leads with brand/model. It explains catalog measurements, exact-model selection, source differences and no-match recovery. Upload explains its intended audience and distinguishes measurement, target and preset files. Required test-equipment metadata remains required; optional hardware metadata is disclosed separately.
- Main comparison save/submission messages are outside auto-collapsed setup. The five-second/same-section rules and Play both action have clearer instructions. Listening requirements, randomization, source matching and contribution eligibility are unchanged.
- Tuning explains sliders by listening effects, uses consistent starting-sound language, explains measured versus unmeasured preview, and accurately labels bypass of added EQ. Quick setup initially shows the existing 10-band PEQdB option (or its actual fallback); all methods and band counts remain available. This is a simpler presentation, not a claim of best sound or a DSP change.
- Downloads distinguish curve CSV data, usable EQ settings, destination apps and the Qudelix manual-entry guide. The administrator-only export-research disclosure remains adjacent and includes measurement-name scope. Exact engine/provenance and headroom details remain accessible.
- Library metadata is optional, source-level matching explains its limits, Flat reference requires an intentional selection, and headphone lookup has explicit loading/no-match/failure states. Ratings are distinguished from sound-setting choices without inventing a new scientific voting question. Suggestions have accurate loading/error/empty/retry states and no longer promise a discussion feature or an audio upload.
- Results lead with personal sound preferences; advanced consistency calculations remain available without presenting a hearing grade. Shared results describe completed runs rather than verified distinct people and retain uncertainty limits.
- Shared results always provide the complete private access URL after the address-bar fragment is removed. Copy failures give a manual alternative. Shared-link explanations name anonymous run-level access, optional setup, curve viewing and possible sharing with the lab owner. Existing access-key protection remains.
- Privacy/data pages summarize required/optional collection and explain browser, private synced and research copies before removal decisions. The broad deletion entry names its sign-out consequence; confirmations retain exact scope. Ordinary participants do not see the owner's historical-transfer tool.
- Sync review shows readable entry counts/titles with full technical values available. Conflict actions explicitly name the entire section they replace. They do not offer unsupported Keep both/per-item merging or weaken concurrency checks.
- Help starts with a first comparison and definitions, then accurate mode-specific shortcuts. Discover, journal, credits, standalone navigation and service errors use clearer wording. Journal failures no longer remain labeled Loading and can be retried. Consent read failure has a retry, stays unsaveable until verified and distinguishes loading from saving.

## Validation and deployment record

Focused actual-component regressions cover failed journal/suggestion reads and retries, complete private-key copying after fragment removal, durable status placement and readable conflict summaries. Existing tests were updated where visible labels changed while retaining behavioral assertions. Final regression totals, lint/types, full build/package, responsive checks and deployment verification are recorded in the release receipt and handoff when completed.

Browser checks use generated measurements/targets and intercepted synthetic transport only. No participant/admin browser account or production contribution is used. Desktop and 360px iframe viewports, keyboard focus, native menu behavior and explicit dark option styling are checked. OS popup pixel capture, screen-reader speech, real novice usability, physical Apple hardware and physical audio remain outside this validation.

The release retains owner-only maintenance. Database/schema/media/recovery semantics are unchanged. Source-only recovery metadata registration is separate from a fresh data recovery point; no redundant data export is requested for this UI/code release. Existing immutable releases and unrelated canonical drafts are preserved. Git author and committer must both remain the lab identity.
