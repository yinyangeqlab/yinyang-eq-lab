# Consolidated data choices and clearer sync controls — October 19, 2026

Owner-authorized release candidate based on update98. Deployment is separate from this implementation report. No schema migration, automatic permission upgrade, account enrollment, publication or backup export is required.

The shared data form has four ongoing choices: comparison participation, identifiable activity monitoring, music details, and one combined Personal research choice. The combined notice explains individual admin research, reviewed public Community group summaries, optional reference checks, collected fields, retention, withdrawal and no historical backfill. Existing partially enabled Personal/Community permissions display a mixed state and remain unchanged unless explicitly edited. One Save records both underlying purpose/version receipts atomically.

Historical-study controls now live in this same form at initial participation and on every review entry point. Current questions, seal timing and permanent-result disclosure accompany each choice. All-current-sharing selects currently available unsealed studies, never unspecified future studies. Required-only and withdrawal clear historical selections. The compatibility historical API and central API use the same rows and server validation. New permission for sealed results, ineligible identities and ordinary archive inclusion of the protected owner account are rejected. YinYangEQ remains excluded unless an account-specific inclusion flow is separately implemented and explicitly authorized.

The two measurement-file approvals also live inside this same data form, opened from Measurements with the actual selected file names. The ordinary initial form explains this scope and how to review it. The sharing shortcut selects contribution of those particular files; rights certification remains an explicit confirmation about those files in the same form. Saving the form does not upload files. Saving the measurement afterward performs the upload. Any change to files or measurement details invalidates approval; cancelled or stale review cannot authorize a changed contribution. Contributed records remain visible/deletable in My data.

Personal and Community tool pages display one read-only combined status and link to the same editor. Current account-based permission tokens are reloaded together after incoming changes, storage changes and focus; stale responses cannot enable contributions and failures clear both tokens. My data and privacy wording point to the same form. Consent choices remain server/account state rather than copied browser snapshot flags.

Participant collection-consent checkboxes were audited across app/components. They reside in comparison-data-settings, including historical and selected-file sections. Other checkboxes control audio/display, selection for public publication, device recovery/replacement, admin verification and service operations; those are contextual action controls rather than research permissions. Public publishing, deletion and device replacement retain their explicit action confirmations.

Sync review distinguishes an account-absent browser copy from a deletion. Add-browser-copy preserves that copy; section removal requires explicit review. Reload/incoming changes discard stale differences, and local changes during conflict review stop the action. No consent choice, source record, or saved browser result is changed by deployment.

Validation includes actual JSX/controller tests, SQLite permission/rollback/withdrawal tests, historical eligibility/notice/sealed guards, combined status races, file approval invalidation, category publication ownership/staleness checks and automatic-sync regressions.
